    02

    돈은 여섯 군데에서 샙니다

    실현 매출 옆에 누수를 같은 축으로 세웠습니다. 막대 하나가 곧 한 개의 실행 과제입니다.

    03

    어느 단계에서 가장 많이 무너지는가

    단계별 잔존율이 아니라 단계별 이탈 인원을 봅니다. 사람 수가 곧 액션의 크기입니다.

    04

    예산은 성과와 반대로 배분돼 있습니다

    지출은 6개 채널에 고르게 뿌려져 있는데, 계약 성과는 전혀 고르지 않습니다.

    실행 도구

    예산 재배분 시뮬레이터

    저효율 채널 예산 중 몇 %를 최고 효율 채널로 옮길지 조절해 보세요. 현재 채널별 ROAS가 유지된다는 가정입니다.

    ※ 선형 외삽 가정입니다. 채널별 수요 상한과 크리에이티브 피로도는 반영되지 않았으므로, 실제로는 8주 단위로 나눠 이전하며 CAC를 추적해야 합니다.

    05

    팔 물건과 원하는 사람이 어긋나 있습니다

    타입별로 남은 재고와 그 타입을 원하는 고객 수를 나란히 놓으면, 어디에 사람을 붙여야 할지 바로 보입니다.

    06

    같은 리드를 받아도 결과가 다릅니다

    상담원별 계약 전환율과 계약 담당자별 해지율. 개인 평가가 아니라 이식할 노하우를 찾기 위한 비교입니다.

    07

    발견 → 근거 → 액션

    각 인사이트는 "무엇을 발견했는가 · 어떤 데이터가 그렇게 말하는가 · 그래서 무엇을 할 것인가" 세 단으로 고정했습니다.

    08

    그래서, 내일 누구에게 전화합니까

    분석의 끝은 리스트여야 합니다. 미계약 고객 —명을 6개 신호로 점수화해 상위 30명을 뽑았습니다. 이 30명의 기대 계약금액은 —입니다.

    점수 산식 (100점 만점)

    ※ 고객 예산과 계약금액은 스케일이 서로 달라(§01) 절대 비교가 불가능하므로, 예산 항목은 전체 고객 대비 상대 백분위로 점수화했습니다.

    행을 클릭하면 점수 구성이 펼쳐집니다. 합성 데이터이므로 연락처는 예시값입니다.

    09

    재현 방법과 한계

    파이프라인

    1. 원본 적재 — data/raw/*.csv 5개 표 4,003행
    2. 정규화 — python pipeline/clean.py 표준 라이브러리만 사용, 외부 의존성 0
    3. 교차 검증 — 표 간 FK·가격 스케일·기간 정합성 확인
    4. 적재 — pipeline/schema.sql + pipeline/seed.sql을 Supabase SQL Editor에서 실행
    5. 배포 — public/ 정적 산출물을 GitHub → Vercel

    정직하게 밝히는 한계

    • 기대매출은 추정치입니다. 미전환 고객의 기대값은 '계약희망 → 계약' 실측 전환율(—)을 적용한 값으로, 확정 매출이 아닙니다.
    • 유입경로 '광고'는 매체가 적혀 있지 않습니다. 남은 유료 채널인 옥외광고로 추정 매핑했고, 해당 레코드는 lead_source_conf='추정'으로 구분했습니다.
    • 광고비는 2025-12까지, 상담·계약은 2026년까지 존재합니다. 채널 ROI는 겹치는 구간만으로 계산했습니다.
    • 광고 리드 수와 고객 수가 대응하지 않습니다. 퍼널은 '고객 등록' 이후만 신뢰 구간으로 사용했습니다.
    • 합성 데이터입니다. 실제 고객·계약·건물과 무관합니다.
